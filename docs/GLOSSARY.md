## Abstract

This document serves as the single source of truth for all normative definitions, technical lexicon, and system terms across the Novelis platform, the Fiction Operating System (FOS), specification standards (NSPEC), and API contracts. Every term SHALL have exactly one normative definition in this document. 

No other specification document may redefine a glossary term. Documents may only reference or extend glossary definitions where explicitly permitted. Any new normative term used across Novelis documentation MUST be added to this Glossary through an approved review prior to normative use.

---

## 1. Platform & System

### Novelis
The umbrella platform and user-facing application providing authors with both Autonomous (One-Click) and Interactive (Co-Pilot) studio authoring environments.

### Fiction Operating System (FOS)
The underlying, deterministic core engine, compiler toolchain, and virtual execution machine responsible for orchestrating, compiling, and executing narrative structures into final literary works.

### Narrative Computing Stack
The 5-layer decoupled architectural framework isolating creative planning (*Thinking*) from deterministic VM execution (*Executing*). See: `NSPEC-000`.

### Entropy Reduction Pipeline
The core architectural law stating that each successive layer in the FOS stack MUST monotonically reduce narrative ambiguity until execution reaches zero logical ambiguity ($H = 0$). See: `NSPEC-000`.

### Build
A single, complete execution session transforming high-level user specifications into one or more compiled narrative artifacts.

### Compilation
The deterministic transformation of validated Story Artifacts into executable narrative representations. Compilation is one discrete phase within a Build.

### Deterministic
A property indicating that identical inputs, specifications, and Runtime conditions MUST always produce identical outputs.

### Autonomous Mode
The operating mode in which Novelis executes the complete Build Pipeline without requiring human intervention after Build initiation.

### Interactive Mode
The operating mode allowing authors to inspect, modify, approve, or reject Story Artifacts throughout the Build lifecycle.

## 2. Creative Planning

### Creative Planning Layer
The isolated multi-agent pipeline responsible for synthesizing raw user prompts into a structured story model.

### Planner Agent
A specialized AI component responsible for generating one aspect of a Story Blueprint, such as Theme, Character, World, or Plot.

### Story Blueprint
A validated, declarative JSON artifact generated by the Creative Planning Layer that defines the global narrative arc, character profiles, world rules, and chapter trajectories. See: `NSPEC-003`.

### Quality Evaluator
A static analysis module (*Static Narrative Linter*) that evaluates a Story Blueprint against structural quality parameters prior to compilation.

### Quality Metrics
The individual evaluative parameters—including Consistency, Pacing, Foreshadowing Density, and Character Arc Velocity—measured by the Quality Evaluator.

### Story Score
The weighted aggregate numerical score computed from Quality Metrics determining whether a Story Blueprint meets the minimum quality threshold for compilation.

## 3. Story Model & State

### Canon
The immutable set of narrative facts considered absolute truth at a given Story Epoch. Canon serves as the single source of truth for the Runtime VM. See: `NSPEC-001`.

### Narrative
The stylistic presentation, prose, and linguistic expression of Canon facts delivered through Renderer Plugins.

### Story Intent
The abstract creative goal and emotional objective formulated by the Creative Planning Layer before structural compilation begins.

### Narrative Arc
A structured progression of narrative objectives connecting the initial story state ($S_0$) to the target ending state ($S_n$).

### Story Epoch
A discrete point in narrative time used as a stable reference for Canon, Character Knowledge, and World State.

### Epistemic Scope
The bounded set of facts, memories, and observations accessible to a specific character at a given Story Epoch. See: `NSPEC-001`.

### Rule Anchor
An unalterable world constraint (physics, magic systems, character mortality) registered within the Rule Engine to strictly reject narrative contradictions.

### Story State
The complete deterministic representation of the fictional world's condition at a specific Story Epoch, including Characters, Locations, Items, Relationships, World Variables, and Canon.

### World State
The subset of Story State representing environmental conditions, locations, global variables, and world rules independent of individual characters.

### Character State
The complete runtime representation of a character, including physical condition, emotional state, inventory, goals, relationships, and epistemic knowledge.

## 4. Compiler & Intermediate Representations (IR)

### Internal Story DSL
A domain-specific, text-based Intermediate Representation (IR) generated internally by transpilers. The Internal Story DSL SHALL NOT be exposed to end users.

### Abstract Syntax Tree (AST)
The hierarchical tree representation produced by parsing the Internal Story DSL, used to validate syntax before compiling to CSIR.

### Canonical Story Intermediate Representation (CSIR)
A strictly structured, canonical JSON payload representing immutable state transition specs, scene objectives, and world constraints. CSIR is the primary input to the Runtime VM. See: `NSPEC-002`.

### Execution Plan
A declarative Directed Acyclic Graph (DAG) describing execution dependencies required to transform Story Artifacts into Runtime State transitions.

---

## 5. Runtime & Execution Engine

### Autonomous Runtime VM
The deterministic execution engine responsible for resolving Directed Acyclic Graphs (DAGs) of scene tasks and evaluating state transitions without creative hallucination. See: `NSPEC-004`.

### Pipeline Manager
The orchestration subsystem coordinating Build phases, scheduling execution tasks, managing retries, and supervising Runtime lifecycle.

### Rule Engine
The deterministic validation subsystem responsible for enforcing Canon, Rule Anchors, Epistemic Constraints, and Runtime consistency.

### Transactional Event Store
An append-only, immutable database (PostgreSQL) recording every state change as a discrete, replayable event.

### State Delta
The net change in world state variables resulting from the execution of a single scene event.

### Self-Healing Loop
An automated rollback and micro-planning pass triggered by the Pipeline Manager when a scene execution violates a Rule Anchor in Autonomous Mode.

### Cancellation Token
A thread-safe cancellation signal that halts execution workers, cancels active model requests, and rolls back uncommitted Event Store transactions upon user request.

## 6. Rendering & Plugins

### Renderer Plugin
A pluggable generation adapter responsible for transforming validated CSIR payloads into natural language prose. See: `NSPEC-007`.

### Rendering Strategy
The prompt formatting and payload delivery strategy selected according to target model capabilities (e.g., Claude XML Tags, OpenAI JSON Schema, Local ChatML).

### Narrative Rendering
The final transformation process converting structured, validated story artifacts into human-readable literary prose.

### Capability Negotiation
The protocol allowing Runtime and Renderer Plugins to determine mutually supported execution features before Rendering begins.

### Plugin
An independently deployable extension implementing one or more official FOS interfaces without modifying the Core Runtime.

### Capability Manifest
A machine-readable declaration describing supported features of a Runtime component, Renderer Plugin, Planner Agent, or Studio Extension.

### Plugin Manifest
A structured metadata document describing plugin identity, version, supported capabilities, dependencies, and compatibility constraints.

## 7. Product Experience

### Novelis Studio
The official integrated authoring environment (IDE) of Novelis, providing One-Click generation, Interactive Mode, visual debugging, inspection, and project management.

### Visual Story Graph
An interactive node-edge graph representation displaying Characters, Scenes, Locations, Events, and their dynamic relationships.

### Story Timeline
A chronological visualization displaying narrative progression, build phases, and historical Event Store transitions.

### Character Inspector
A UI panel displaying live Character State, BDI-M profile, inventory, relational vectors, and epistemic boundaries.

### Conflict Resolver
An interactive interface presented to the user when the Runtime VM requests human intervention for unresolved narrative conflicts in Interactive Mode.

### Build Dashboard
The primary monitoring view rendering real-time build progress, active telemetry streams, Story Score evolution, and runtime diagnostics.

## 8. API & Integration

### Dual-Plane API Architecture
The separation of system communications into a REST Control Plane and an SSE Telemetry Plane. See: `API-SPEC`.

### Control Plane
An OpenAPI 3.1 compliant HTTP REST interface managing project lifecycle, system settings, and explicit build state commands (Start, Pause, Resume, Abort).

### Telemetry Plane
An AsyncAPI 3.0 compliant Server-Sent Events (SSE) stream broadcasting real-time execution progress, live graph deltas, build logs, and quality scores.

### Build Telemetry
Real-time operational events emitted over the Telemetry Plane describing progress percentage, estimated time remaining, active tasks, and status changes.

### Build State Machine
The formal 10-state lifecycle governing build execution: `QUEUED`, `PLANNING`, `COMPILING`, `VALIDATING`, `RENDERING`, `EXPORTING`, `FINISHED`, `FAILED`, `PAUSED`, and `CANCELLED`.

### Heartbeat Stream (`system.heartbeat`)
A mandatory telemetry event transmitted every 15 seconds to maintain active HTTP connection status and report worker node health.

## 9. Documentation & Artifacts

### Artifact
Any inspectable, reproducible, versioned output generated by a pipeline stage.

### Story Artifact
Any narrative-specific artifact produced during the Story Build process, including Story Blueprints, CSIR payloads, Event Logs, Snapshots, Story Graphs, and Rendered Chapters.

### Build Artifact
Any persistent output produced during a Build, including Story Blueprints, CSIR files, Event Logs, State Snapshots, or Rendered Novels.

### NSPEC
The official normative specification document series defining the architecture, standards, and protocols of the Novelis ecosystem.

### ADR (Architecture Decision Record)
A document capturing a significant architectural decision made by the team, including context and consequences.

### RFC (Request for Comments)
A formal proposal document submitted to modify or expand an NSPEC standard prior to ratification.

### API-SPEC
The normative specification describing REST APIs, Telemetry Event schemas, Data Plane payloads, and version compatibility rules.

## 11. Narrative Memory & Retrieval Systems

### Story Bible
The structured, relational repository (implemented as an embedded SQLite database) serving as the authoritative storage for Hard Canon entities, world rules, character relationships, and plot threads. See: `NSPEC-002`.

### Hard Canon
Factual, non-negotiable assertions within the fictional universe (e.g., character physical traits, living status, locations, established history) that are stored as structured tabular records rather than approximate vector embeddings.

### Hybrid Retrieval
A multi-modal search methodology combining dense vector similarity (semantic context) and sparse lexical inverted indexing (exact keyword/entity matching) to ensure accurate recall of narrative lore and proper names.

### Dense-Sparse Representation
A dual embedding vector standard (such as BGE-M3) that concurrently outputs dense semantic vectors for conceptual context and sparse lexical token weights for exact named entity preservation.

### Reranker
A cross-encoder model (such as bge-reranker-v2-m3) that scores and re-evaluates a wide candidate pool of retrieved scene chunks (e.g., top 30) down to a concentrated, highly relevant context window (e.g., top 5–8).

### Hierarchical Summarization Tree
A multi-tier recursive summary structure consisting of Scene, Chapter, Arc, and Book synopses that allows generative models to maintain macroscopic narrative awareness without exceeding context limits.

### Plot Thread
An explicit, tracked narrative promise or unresolved tension (Chekhov's Gun) initialized at an earlier epoch with defined lifecycle states: `OPEN`, `PROGRESSING`, and `RESOLVED`.

### Consistency Validation Loop
A secondary evaluative LLM pass that cross-references newly drafted prose against the Story Bible and flagged narrative rules to detect and rectify canon contradictions before state commitment.

### Fact Extraction Pipeline
An automated extraction process executed post-scene generation that parses new narrative assertions, updates character knowledge states, and commits state deltas back to the Story Bible.
